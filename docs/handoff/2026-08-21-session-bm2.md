## 1. 🔴 The two plant findings are ONE defect, seen from each end

> _"If I change the sources and press UPDATE, nothing happens — but pressing the LOOK buttons performs
> a take again. If I'm on 2-box, change `l-1`'s source and press look-1, then when we go to solo **it
> shows the OLD source for a moment and then switches to the new one.**"_

They read as two bugs — a dead button and a video glitch. **Established from the code and pinned on
the wire** (`live-look-reconcile`, _"an assignment change LURKS…"_):

1. `setSourceAssignments` writes the map and emits. **It does not reconcile.** The operator's
   _"nothing happens"_ is the product working as built.
2. It lands at the **next reconcile from ANY cause** — and a look press is one. That is the second
   apply path.
3. Because it lands **during** the switch, the seat's producer changes **inside** it: a `PLAY`
   (a replace) on a layer whose hole is moving. **That is the flash.** An ordinary (B′) switch is
   pure `MIXER FILL` and cannot flash; it needs a producer change in the same action, and the
   lurking assignment is what puts one there.

⚠ **`STAGED` was never the leak.** A staged Inspector edit has never been sent — the bridge cannot
apply what it was not told. What lurks is an **APPLIED** assignment. Both are asserted, because "the
look button applied my edit" is true of one and false of the other.

## 2. 🔴 What is NOT fixed, stated before what is

narrowing runs against `@cg/amcp-mock`, which is precisely the thing that models the behaviour in

  `MIXER … DEFER` with a channel-scoped `COMMIT` and forbids both until the COMMIT-scope question is

**The probes it waits on are `6.9a` and `§3b`**, and the frame count at 25 fps is still owed — this
session had no plant access, so it is not a number I can supply. All of that is in `tasks.md` 7.15,

## 3. What landed

- **`LOOK INPUTS`** — each look, its own per-plate input, the LIVE one marked (amber, `ON AIR NOW`;
  **not green** — green is the layer table's ON AIR and means something else). It sits under the
  template DEFAULT it falls back to, so the levels read top-down in resolution order.
- **ONE atomic UPDATE.** `stack.update` carries `lookBindings` — the row's COMPLETE map, because a
  merge-only payload can add and change but never CLEAR. The bridge applies bindings → reconciles
  fills → tells the page, and a refused binding refuses the whole update.
  **Mutation-checked:** moving the bindings after the field intent reddens the atomicity tests with
  the exact symptom — the text landing when the binding was refused.
- **§2's masking hazard closed.** A patch is named on every row it masks; the masked value is struck
  through and labelled _"not in force — patched to X"_ (never greyed: grey reads as _disabled_, and
  the operator must be able to tell _overridden_ from _broken_); the control stays editable and says
  _"takes effect when the patch is cleared"_ **visibly** — `DraftChip` carries its label as an
  `aria-label` only, so putting it there would have been screen-reader-only; and **CLEAR PATCH** sits
  on the row that shows the patch.
- **§3.4's sentence rewritten.** _"Set for the template, not this row"_ was true of a flat map and is
  a lie about a four-level one — it says "not this row" while two of the four levels are this row's.
