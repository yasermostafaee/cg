## 2. The shape of the fix

- **One decision function** (`requestGuardedAdd`, `features/addGuard/duration-guard.ts`) holds
  the pending state and the strict `contentMs > hostMs` comparison; three kind adapters derive
  the intrinsic facts at the unit edge (video `durationMs`; Lottie `(op − ip)/fr` at 1× — the
  creation default, an authored speed cannot apply to an element that does not exist; a
  composition child's `activeRangeOf` length). Host length: `activeRangeOf(activeDocOf(scene))`
  — the verified single authority, reused.
- **Extend** goes through the duration row's OWN action (`setSceneDurationFrames`) plus
  `setSceneActiveOut` when an explicit active range exists (the compared length is the ACTIVE
  window — extending only the total would leave content truncated by the play window), wrapped
  in `runAsSingleHistoryEntry` with the add: ONE undo restores duration and element together
  (pinned).
- **Backdrop** writes `phases.source: 'composition'` with the claim-least slots — now EXTRACTED
  to `state/follow-attach.ts` and shared with the Inspector's attach buttons (two writers, one
  seed rule — the session-P extraction discipline). A clip that arrived with bodymovin markers
  keeps its marker values and just takes the source (session S's attach-from-markers semantics).
  `holdAt` is not asked; the Inspector tunes it. The choice is offered even on a no-lifecycle
  host — the E2E pins that the added follower then presents the §9.1 "following nothing yet"
  explanation.
- **Cancel** (and Escape, and backdrop-click) leaves the scene OBJECT-IDENTICAL — pending state
  lives outside the store, so nothing enters undo history.
- **Composition inserts get the firm TWO-choice dialog** — an instance has no `phases` and
  cannot follow; recorded in the D-151 item as scoping on the settled answer. The D-086 cycle
  guard still runs INSIDE `addCompositionInstance` at commit time; the C2 door keeps its exact
  loop-notice via a pre-check.

## 4. ⚠ Ten existing E2E specs changed — the sanctioned case, stated plainly

The guard is a DELIBERATE behaviour change on the add path, and the E2E suite promptly proved it
covers the doors: every spec that drops a 1.6 s video fixture or a 2–4 s Lottie into the 1 s
default project now meets the dialog, and their flows failed on its backdrop. Per the repair
rules this is the one case where tests may change — the OpenSpec spec for this change made
oversized adds interactive — so those specs were adapted, assertions untouched:

- `video-import` / `video-preview-rebuild` / `video-dimensions` / `video-export` /
  `lottie-element` / `lottie-override` / `lottie-entrance-settle` (reordered its existing
  stretch to BEFORE the drop): the host is pre-sized to fit the clip
  (`app.setSceneDuration(...)` after `newProject`), because those specs test import, render,
  transplant, export, override, and settle mechanics — not the guard.
- `lottie-auto-exit` DELIBERATELY pairs a 4 s clip with a 1 s host (the outro plays on exit,
  outside the timeline). It now places through a fitting host and shrinks back to 50 frames —
  the guard is ADD-time only, so the end state is byte-equal to the original scenario and every
  sub-second timing stays valid. This also demonstrates the item's own scoping: no re-check
  ever fires on content already accepted.
- `video-canvas-render` surfaced only in the FULL-suite run — its drop is hand-rolled
  (synthetic dragover/drop events), so the `dragTo` sweep missed it. Same pre-size adaptation.
  Worth remembering: a door sweep keyed on the harness's drag helper misses a hand-rolled drop;
  the full suite is the sweep that cannot be fooled.
- Composition-nesting specs needed nothing: panel-created comps share the default duration and
  the comparison is strictly greater-than.
