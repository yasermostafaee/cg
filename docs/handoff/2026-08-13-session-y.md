# Handoff — 2026-08-13, session Y (design correction: a follower's outro is the clip's own ending)

## 0. Why two instrumented investigations found nothing

Sessions V and X were real investigations that found no bug — because there was no bug where
they were licensed to look. Both instrumented BELOW the specification: driver options, exit
ledgers, elapsed anchors, hold sources — and every mechanism measured sound, because the
runtime was faithfully implementing `media-phases-follow-composition` §2 as written. **The
defect was the specification itself** — the outro window `[H → H + outSpan]` is, for a real
furniture clip, its motionless middle — and the spec was not in either session's scope: V was
a fix session bound by "do not change the outro rule", X was bound the same way plus an
explicit rule-confirmation (§10.1). The owner's two paired project files finally put numbers
on it, and this session corrected the rule itself.

## 1. The evidence and the error, named

`normal.cgproj` / `follow.cgproj` — the same scene before/after attaching follow; the clip is
358 frames @ 25 fps, 1:1 with the composition. His clip: intro `0 → 125`, static `125 → 260`,
authored build-off `260 → 358`; `contentStart 125`, `outPoint 260` — set from the clip,
deliberately. The old rule derived the outro as clip `[125 → 223]` — **the static middle** —
and frames `223 → 358`, the whole authored build-off, never played anywhere. End-anchored, the
same numbers give `[260 → 358]`: his build-off exactly, no extra authoring. The old §2.1
rejection of end-anchoring rested on a pop that CANNOT occur on the clips this feature targets
(static between build-on and build-off); that text is kept verbatim in §2.1 as the record of
what was wrong.

## 2. The corrected rule (design.md §2, §11; spec deltas re-stated)

**A follower's outro is the clip's own ending. Follow decides WHEN phases happen, never WHICH
frames the ending consists of.**

- No authored phases: outro `[clipEnd − outSpan → clipEnd]`, landing on the last frame at
  removal. Intro/hold UNCHANGED (`[H − entranceSpan → H]`, freeze at `H`) — byte-identical
  assertions carried through every re-pinned suite.
- Authored phases (`introEnd`/`outroStart`, markers or manual): **they WIN** — intro
  `[0 → introEnd]` scheduled (a new `introDelayMs` in both drivers' ONE mappings) to finish at
  the content start; hold = `introEnd`; outro `[outroStart → clipEnd]` from the OUT phase.
- `holdAt` is meaningful only without an authored intro; the Inspector explains instead of
  showing a dead input.
- Flags (all through the one hint surface): `wholeClipOutro`, `outroCutByRemoval`,
  `lateSettle`, and `holdJump` — the deliberately-accepted hold→outro seam jump, named with
  BOTH clip times. `outroClamped` (an artefact of the old anchor) is gone.

## 3. The stored lie, resolved

Attach used to WRITE seed values (`introEnd: durationMs/2`, `outroStart: durationMs`) into
elements that had none — ignored then, but under the corrected rule they would masquerade as
authored intent. Decided and recorded: `introEnd`/`outroStart` are now OPTIONAL in both phase
schemas; **attach writes `{source: 'composition'}` alone** (Inspector buttons and the D-151
backdrop route share the one seed rule); the pre-Y **seed signature derives as if absent** via
one discrimination per kind (`videoFollowClipFacts` / `lottieFollowClipFacts`), so every
already-saved follow scene — the owner's included — derives correctly with no migration.
**Detach bakes truthfully**: the derived hold + the clip's own outro start (manual then plays
exactly what follow was playing). Corner accepted and recorded: a hand-authored value equal to
the seed derives as derived.
