  no-op while the driver runs or holds its own lifecycle; skip (never queue) while `seeking()`;
  a degenerate outro (`outroStart >= outroEnd`) takes the INTRO mapping past the out-point (the

  spies the prototype method and asserts the seek equals the mapping's own return value.

  (`drivesHold` unread), §9.3 (a) (no direction branch anywhere), follow windows compose for

  `expectedClipMs`.

## 3. The consistency debt — paid, with the poster kept subordinate

The canvas `<video>` no longer RESTS on `data-cg-poster-ms`. But the poster routine was never
only a seek — it is the eager-load path and the sequential 16× recovery for pre-`2026-07-25.5`
seek-fragile assets, plus the one place a load error reaches the console. **The recovery path IS
load-bearing on the canvas for old assets** (removing it would make the first operation a cold
seek — the terminal `PIPELINE_ERROR_DECODE` class), so it stays, subordinate to the tick:

- the iframe chains `runtime.tick(currentFrame)` onto the routine's settle (guarded `!playing`),
- and `applyScene` re-ticks after `applyAssetUrls`, because `reconcileVideos` transplants a
  pooled node over the one the build-time tick just positioned.

So the paint order is deterministic — load → (poster transient →) tick — and the settled frame is
ALWAYS the playhead's, including a build-on clip's transparent frame 0 at rest, which is exactly
what the Lottie shows and what the owner accepted watching the real canvas (design §4.3). The
poster is a PRE-TICK TRANSIENT for video precisely as it already was for the Lottie. Recorded in
`design.md` §9.5's debt subsection ("How it was paid").
